# 应用级技术方案（v2 · 最终实施版）

> 从「两段式 demo」升级为「应用级情感陪伴助手」，已全部落地并通过真实 LLM 联调。

## 1. 目标与达成情况

| 维度 | demo 现状 | 应用级目标 | 达成 |
|------|----------|-----------|------|
| 流程 | 识别 → 单次回应 | 记忆检索→识别→生成→记忆回写闭环 | ✅ |
| 对话 | 单轮无上下文 | 多轮，回应可引用历史 | ✅ |
| 记忆 | 无 | 短期窗口 + 长期画像（SQLite 持久） | ✅ |
| 会话 | 无隔离 | session_id 多会话隔离 | ✅ |
| 提示词 | 内联 f-string | Jinja2 模板集中管理（五段式） | ✅ |
| 实体 | 散落 dict | pydantic 唯一实体源 | ✅ |
| 结构 | 平铺脚本 | 分层 package（core/storage/flows/api） | ✅ |

## 2. 总体架构

```
┌──────────────┐  POST /chat{ session_id, text }  ┌───────────────────────────────┐
│  前端进程     │ ───────────────────────────────▶ │  后端进程（编排层 flows/）      │
│  Streamlit   │                                  │                               │
│  会话切换/新建 │ ◀─────────────────────────────── │ [检索]→[识别]→[生成分支]→[回写]  │
└──────────────┘  { sentiment, intensity, reply,  │       ↕                       │
                   memory_summary }              │  ┌─────────────────────────┐ │
                                                 │  │ 存储层 storage/           │ │
                                                 │  │ SQLite: sessions/        │ │
                                                 │  │ messages / memories     │ │
                                                 │  └─────────────────────────┘ │
                                                 │  LangGraph 或 OpenAI-Agents   │
                                                 └───────────────────────────────┘
```

## 3. Agent 分类（四类职责 × 两框架落地）

| # | 职责 | LangGraph（节点） | OpenAI-Agents（Agent） |
|---|------|------------------|------------------------|
| 1 | 记忆检索 | `retrieve_memory` | 主流程调 storage 层 |
| 2 | 情感识别（进程1） | `classify`（json_mode 结构化） | `sentiment_agent`（output_type） |
| 3 | 回应生成（进程2） | `cheer / comfort / neutral` 三节点（条件边路由） | `cheer / comfort / neutral` 三 Agent（字典分派） |
| 4 | 记忆回写 | `store_memory` | `memory_update_agent` + 主流程写 storage |

## 4. 提示词系统（Jinja2）

- 模板集中于 `prompts/*.j2`，五段式：**角色 / 任务 / 约束 / 变量 / 输出格式**。
- `core/prompt_manager.py` 用 `StrictUndefined` 渲染——变量缺失立即报错，
  杜绝提示词静默劣化。
- 变量注入：`text`（本轮）、`history`（短期记忆）、`memory`（长期画像）、
  `exchange`（本轮用户+助手对话）、`existing_events / existing_topics`（既有记忆）。
- **两框架共用同一套模板**，保证对比公平。

## 5. pydantic 实体（core/entities.py）

| 实体 | 用途 |
|------|------|
| `Sentiment` / `Intensity` 枚举 | 三分类 + 三档强度 |
| `SentimentResult` | 进程1 结构化输出（两框架共用） |
| `MemoryUpdateResult` | 记忆提炼结构化输出 |
| `Session` / `Message` / `Memory` | 存储层领域实体 |
| `ChatRequest` / `ChatResponse` / `SessionDetail` | API 出入参 |

## 6. 记忆系统

| 层级 | 内容 | 存储 | 窗口/上限 |
|------|------|------|----------|
| 短期 | 会话内多轮消息 | `messages` 表 | 最近 10 条（`MEMORY_WINDOW` 可配） |
| 长期·趋势 | 正/负/中计数 | `memories[emotion_trend]` | 程序化维护，无 LLM |
| 长期·事件 | 关键事件 | `memories[key_events]` | LLM 提炼，≤10 条，去重合并 |
| 长期·主题 | 常聊话题 | `memories[topics]` | LLM 提炼，≤10 条 |
| 长期·摘要 | 近况概括 | `memories[last_summary]` | LLM 每轮滚动更新 |

检索时渲染为文本注入回应 prompt（"情绪趋势/关键事件/常聊主题/用户近况"四行）。

## 7. 结构化输出兼容性（关键实测结论）

DeepSeek `deepseek-flash` 为思考模型：

| 能力 | 结果 | 采用方案 |
|------|------|---------|
| `response_format=json_schema` | ❌ 400 | LangGraph 弃用默认方法 |
| `response_format=json_object`（json_mode） | ✅ | LangGraph `with_structured_output(method="json_mode")` |
| 强制 tool_choice | ❌ 400 | 不使用 |
| tool_choice=auto | ✅ | openai-agents `output_type` 即此路径 |
| 纯文本 JSON | ✅ | `extract_json_dict` 兜底（去围栏→直解→正则） |

降级链：**框架原生结构化 → 文本 JSON 提取 → 关键词兜底**；
长期记忆失败不阻塞主回应。

## 8. API 设计

```
POST   /chat             { session_id?, text } → { session_id, framework,
                                                    sentiment, intensity, reply,
                                                    memory_summary }
GET    /sessions          → 会话列表
GET    /sessions/{id}     → { session, messages, memories }
DELETE /sessions/{id}     → 删除会话 + 消息 + 记忆
GET    /health
```

两后端共用 `api/server_factory.py` 工厂，路由行为完全一致；`run_pipeline`
同步/异步自适应（langgraph 同步、agents 异步）。
